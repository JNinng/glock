# 所有变更操作携带栅栏代际

锁的后端记录里保存当前栅栏代际（fencing generation），每次获取事件递增；句柄发出的每个变更操作（Release、Refresh、Downgrade）携带签发时的代际，代际不符即拒绝。

原因：`WithOwner` 允许 token 跨进程存活重用（WAL 恢复场景走 `Acquire + WithOwner`）。若释放只校验 Owner Token，崩溃前滞留网络的旧
Release 会在重新获取后到达并误删新持有——防误删在时间维度上的漏洞。代际校验把它堵死：旧代际操作必然被拒。

## Consequences

- 公开的 Fencing Token 与内部代际是同一个计数器（强制契约，见 ADR-0004），业务侧直接可用于下游写入防护。
- 可重入的计数递增沿用当前代际；只有获取事件递增代际。
- 崩溃恢复不设专门动词：重入会叠上崩溃前的残留计数，由租约到期清除，释放后最多多占用一个租约期。
